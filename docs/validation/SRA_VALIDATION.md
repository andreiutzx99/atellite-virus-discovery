# SRA Toolkit software validation

On 2026-09-24, the official Windows SRA Toolkit 3.4.1 archive was downloaded over HTTPS, checked against NCBI's published MD5 (`adb911959f366f3e3de1f140128d4b23`) and independently SHA256-recorded. No system installation or persistent PATH change was made.

The benchmark was [SRR12086795](https://www.ebi.ac.uk/ena/browser/view/SRR12086795), annotated by ENA as *Saccharomyces cerevisiae* brewing-yeast WGS, paired layout, study PRJNA641752. This was a small software-format check, not discovery analysis. The archive was 80,055 bytes. `prefetch` completed with a 50 MB maximum-size setting and a 60-second timeout. The adapter ran `fasterq-dump`, produced two FASTQ files with two records each, validated syntax/counts/paired identifiers, wrote deterministic gzip outputs, recorded tool/input/output hashes, cleaned successful scratch, and reused the completed conversion without rewriting its manifest.

The [machine-readable evidence](sra-toolkit-3.4.1.json) records acquisition/conversion commands with local path prefixes removed, metadata, timestamps, executable/archive/output hashes and outcomes. Toolkit source: [official download page](https://github.com/ncbi/sra-tools/wiki/01.-Downloading-SRA-Toolkit); conversion guidance: [NCBI fasterq-dump documentation](https://github.com/ncbi/sra-tools/wiki/HowTo:-fasterq-dump).

Validation limits: one tiny paired accession, Windows Toolkit 3.4.1. Single-end conversion, absent/inconsistent mates, malformed/empty FASTQ, timeout/retry isolation, invalid executables and disk failures use artificial process fixtures. They are genuine software tests, but do not establish live single-end, long-read, large-archive, cloud-authentication, native Linux Toolkit or interrupted-network behavior. Existing downloader tests exercise mocked network interruption/resume separately. The live benchmark is not fetched automatically by ordinary CI and is not wired into the project's biological dataset search.
